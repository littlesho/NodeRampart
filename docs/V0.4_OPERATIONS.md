## Local package installation

<a id="local-installation-before-publication"></a>

### Installing a reviewed native package

For an ordinary server, prefer a native package supplied by a trusted build.
The server needs systemd and root access. Choose the package for its distribution
and architecture; `uname -m` reports `x86_64` or `aarch64` on the targeted systems.
Debian calls these architectures `amd64` and `arm64`.

<!-- current-release:start -->
Published alpha.9, Debian amd64 example, from the directory containing the reviewed package:

```sh
sudo apt update
sudo apt install ./noderampart_0.4.0-alpha.9_amd64.deb
sudo noderampart setup
```

Published alpha.9, Fedora 44 x86_64 example:

```sh
sudo dnf install ./noderampart-0.4.0-0.alpha.10.fc44.x86_64.rpm
sudo noderampart setup
```

<!-- current-release:end -->

For Fedora 43 use the `fc43` package; for ARM64 use `_arm64.deb` or `.aarch64.rpm`.
apt/dnf install declared dependencies. Keep repository signature checks enabled.
If local policy requires signed RPMs, obtain an appropriately signed package;
the bootstrap does not override that policy.

**A fresh Debian package enables and starts observation with safe defaults,
subject to system service policy. Fedora follows its service presets.** Telegram
is disabled and GeoIP/price downloads are optional. The setup menu's Start action
explicitly enables the services using the configuration you have chosen.

原生安装包会自动处理依赖。Debian 首次安装会按系统策略启用服务并以默认配置开始
观察，Fedora 遵循 preset；TUI 中的“启动已配置服务”用于确认启用您选定的配置。
已有安装升级时保留启用、禁用和 mask 状态。

### Building a package yourself

Run builds without root from the repository root, using Go 1.25 or newer and
make. Download dependencies on the build machine; the resulting server package
does not require Go. Debian packaging additionally needs `dpkg-deb`; Fedora
packaging needs Python 3, `rpm-build`, `systemd-rpm-macros` and the spec's build dependencies.
Use a Fedora 43 or 44 build environment to produce that distribution's RPM.

For an uncommitted local candidate, declare its build identity honestly and
retain the actual inputs/package hashes:

```sh
# Local Debian candidate; build metadata must match ARCH.
GOOS=linux GOARCH=amd64 make build COMMIT=unknown
ARCH=amd64 ./scripts/build-deb.sh

# Local RPM candidate; run in a Fedora 44 build environment.
ARCH=amd64 COMMIT=unknown ./scripts/build-rpm.sh
```

Local development package identities come from the checked-out `VERSION` and
packaging mappings; they are separate from [LATEST_RELEASE](../LATEST_RELEASE).
Use the filenames reported by `build-deb.sh` / `build-rpm.sh`. Debian prerelease
native versions use `~`, while public release filenames use the product tag
without `v`. RPM's Release index has its own mapping. RPM staging uses the
explicit source manifest and verified module inputs. Go 1.25.0 is the declared
minimum; current validation used Go 1.26.8. Hosted Debian/SBOM inspection pins
Go 1.26.8; Fedora uses its native distribution Go toolchain with
`GOTOOLCHAIN=local`, recorded separately in buildinfo.

Formal release builds require a clean checkout and explicit metadata:
`COMMIT` must equal full 40-character HEAD and `BUILD_DATE` must equal that
commit's timestamp. Empty workflow outputs cannot fall back to local Git/time;
tracked changes or untracked source inputs are rejected. Inspect the two lines
from the fixed metadata helper, then declare those exact values:

```sh
EXPECTED_COMMIT=$(git rev-parse HEAD) ./scripts/release-metadata.sh
# Confirm the helper output matches the intended clean source, then declare it.
COMMIT=$(git rev-parse --verify HEAD^{commit})
BUILD_DATE=$(git show -s --format=%cI "$COMMIT")
export COMMIT BUILD_DATE
./scripts/validate.sh
./scripts/build-release.sh --deb amd64
# In the matching Fedora build environment, with the same explicit metadata:
./scripts/build-release.sh --rpm amd64
```

Confirm these declarations match the inspected helper output; missing/incorrect
values fail. Run shared validation on the candidate before packaging/distribution.
The builder/collector does not publish, move tags, change `VERSION` or prove
hosted workflow execution. See [release verification](RELEASE_VERIFICATION.md).

<!-- current-release:start -->
For comparison, current published DEB assets use
`noderampart_0.4.0-alpha.9_ARCH.deb` with internal `0.4.0~alpha.9`; RPM uses
`0.4.0-0.alpha.10.fcXX`. A local artifact with the same version still has its own
source and byte identity.
<!-- current-release:end -->

未提交的本地候选用 `COMMIT=unknown` 的普通 build/package 命令，并保留真实输入和
产物摘要。正式 `build-release.sh` 要求显式完整 COMMIT 等于 HEAD、BUILD_DATE
等于该提交时间，并拒绝源码改动或未跟踪输入。先核对 helper 输出，再填写原值。
开发产物按当前 `VERSION` 和打包映射命名；公开包按实际 Release 记录核验。

Use `arm64` in place of `amd64` for the other target. Cross-compilation and
metadata checks do not prove that the program has run on real ARM64 hardware.
See [development validation](DEVELOPMENT.md) before distributing a build.

For a source installation, build binaries and use the source installer instead:

```sh
make build COMMIT=unknown
sudo ./scripts/install.sh
sudo /usr/local/bin/noderampart setup
```

Repeating a source installation preserves each service's enabled and running state. A permanent mask occupies the source unit file path, so installation refuses it before making changes; runtime masks remain in place.

The source installer requires existing system utilities including systemd and
user/group administration commands. Native packages are the automatic dependency
installation path. Source installations use `/usr/local/bin`; native packages
use `/usr/bin`. Do not install both over one another.

### The maintained and frozen bootstraps

The [maintained main entry](../README.md#install-the-newest-published-release)
resolves the highest published product version, including prereleases, and
prints one selected tag when `--version` is omitted. It fetches that Release's
`SHA256SUMS` and bootstrap, verifies the script digest, then runs it once with
the explicit pinned tag. The Release script downloads and checks the matching
native package. All stages keep that same version, even if a new Release appears.
Downloads and API pagination have size, count and time limits; incomplete
selection, API failures, missing packages or failed checks stop installation
without an older-version fallback. Explicit pins skip default-list resolution.

The maintained entry requires Python 3 and util-linux `prlimit` in addition to
curl and HTTPS certificates; these are installer-only dependencies and must be
available before default resolution. Existing source-install conflicts and
package downgrade checks remain effective. HTTPS and same-release SHA256 checks
provide content consistency; [attestation verification](RELEASE_VERIFICATION.md#download-and-verify)
is separate.

<!-- current-release:start -->
To pin the current release, pass `--version v0.4.0-alpha.9`. When downloading
`bootstrap.sh` from that Release, **always pass this explicit version**: published
bootstrap bytes preserve their historical default. Supported options also include
`--no-setup` and the equivalent `--non-interactive`.
<!-- current-release:end -->

The default path requires a controlling terminal. It opens `/dev/tty` after
installation, so configuration input is independent of the downloaded script
pipe. Do not use `sudo -S` with that pipe. For automation, pass `--no-setup`, then
open `sudo noderampart setup` in a terminal later. This flag skips the menu; it
does not change the native package's initial service policy.

## Configuration and recovery

Open `sudo noderampart setup` for onboarding or `sudo noderampart tui` for the main
menu. Use `--language en` or `--language zh` after the subcommand to choose a
language. An SSH session needs a terminal, for example an existing interactive
SSH login or `ssh -t` with your own destination.

Use **Configuration** to edit grouped fields. Review shows each effective old → new value in a scrollable page before final confirmation; reverting a field to its original value removes it from the diff. Changes remain a draft until you
validate, review and confirm Save. Escape/back lets you discard the draft. The
menu checks the whole configuration, preserves advanced fields and rejects a
save if another process edited the file after it was loaded.

The managed file is **`/etc/noderampart/config.json`**. This is also the path used
by the installed daemon, sensor and optional GeoIP timer. Management commands
reject an alternate config path. Existing noninteractive CLI commands still
accept `--config`; operating another configuration requires coordinating the
service units manually.

配置菜单覆盖接口、SSH、阈值、通知、日报、GeoIP、隐私、价格、存储及高级路径设置。
修改先保存在草稿里，验证并确认后才写入固定配置文件。改变数据库路径不会搬迁历史数据，
改变接口可能导致短暂采集中断；先查看健康记录，再判断某一时段是否完整。

| Choice | Practical guidance |
| --- | --- |
| Interfaces | Leave both selections empty to follow IPv4/IPv6 default routes. Select explicit names for policy routing or unusual networks. Avoid monitoring overlapping bridge/tunnel paths when comparing totals. |
| Thresholds | Inspect normal usage first. Thresholds apply per interface; tune for your actual traffic. |
| Reports | Choose your timezone and daily time. Historical backfill can generate reports from stored observations, but cannot recreate missing collection. |
| Privacy | Prefix storage is the default. Hash mode needs a persistent key; changing keys prevents historical identity comparisons. |
| Storage and paths | Database paths stay under `/var/lib/noderampart`; sockets stay under `/run/noderampart`. The menu does not migrate a database or weaken the service sandbox. |

Saving restarts the affected running services as required while retaining
disabled or masked states. A failed activation attempts to restore the prior
configuration and service state. If interrupted, use **Services and uninstall →
Recover previous configuration** before further edits. Recovery reports
conflicts instead of replacing a file changed by another administrator. It does
not downgrade a database.

While a service is activating, deactivating or reloading, configuration apply
and restart refuse the operation; wait for its transition to settle. Failed
services remain visibly failed. Readiness verifies the loaded configuration
fingerprint, storage and interface collection, plus sensor data when requested.
It allows two sampling periods plus five seconds (at least eight seconds), so a
one-minute period is valid. Optional notification or GeoIP degradation does not
block basic readiness, and no SSH login is required.

**Stop services** remains available when configuration JSON is broken, including
from the Services menu after a configuration-load error. Start, restart and
save still require valid configuration. Configuration recovery records now
retain version, phase, timestamps, fingerprints and stable failure codes;
version 1 records remain readable. Recovery restores service intent even when
configuration bytes have already been restored. Keep the record while recovery
is incomplete; restore missing dependencies and retry rather than deleting it.

取消普通管理命令时会收尾其受控进程组并核验后代退出。卸载则请求已安装 helper
协作取消：已经进入的包管理事务继续受监督并保留管理锁，事务完成后停止派发下一步，
不会强杀 dpkg/rpm。界面显示“取消已请求 / 正在收尾 / 安装状态需检查”，期间不要重试
其他管理动作。systemd 已接收的作业须通过实际服务状态确认，终止 helper 不代表撤销作业。

Cancellation cleans up the controlled process group for ordinary management
commands and checks that descendants have exited. Removal requests cooperative
cancellation from the installed helper: an entered package transaction keeps
running under supervision and retains the management lock, then no later action
is dispatched. The UI reports cancellation requested, finishing, and installation
state needing inspection. Inspect actual service state for jobs already handed
to systemd; terminating a helper does not revoke such jobs.
An uninterruptible OS process can keep cleanup pending after a deadline; the
supervisor retains its own lock until actual exit is confirmed. A deadline or
successful signal delivery is not proof that an operation has stopped.

服务处于启动、停止或重新加载过渡状态时，保存/重启会明确拒绝，请等待状态稳定；失败状态
也不会显示成主动停止。就绪检查确认有效配置指纹、存储和网卡采集，并在需要时确认 sensor
批次，等待至少 8 秒或两个采样周期加 5 秒；不依赖一次 SSH 登录，也不因可选外发故障阻止
基础就绪。配置 JSON 损坏时仍可从服务菜单停止固定服务，启动、重启和保存仍须验证配置。
恢复记录保留版本、阶段、时间、指纹与原因码，兼容旧记录；文件已经还原也必须恢复服务状态。
不可中断的内核操作可能令超时后的收尾继续等待；监督者仍保留自己的锁，确认实际退出后才释放。

For a manual edit, validate before an intentional restart:

```sh
sudo noderampart config test
sudo systemctl restart noderampartd.service noderampart-sensor.service
sudo noderampart doctor
sudo noderampart status
```

That explicit restart starts stopped services; use the TUI save operation if you
want its service-state preservation. If status cannot connect, inspect
`sudo systemctl status noderampartd.service noderampart-sensor.service` and the
local journal. Do not delete the management lock to bypass an active operation.

## Timezone selector and Telegram language

This feature is included in the current release and was introduced in published alpha.7. Frozen alpha.6 packages do not acquire
these features. Local/CI candidate declarations remain separate from the exact
published C/package bytes recorded in [release verification](RELEASE_VERIFICATION.md#alpha7-publication-and-distribution-verification).

Open `sudo noderampart setup` or `sudo noderampart tui`. In **Configuration →
Daily reports → Report timezone**, browse the list or search for a common
Chinese city name, an English name, an IANA identifier or `UTC+05:45`. Use Down
to move from search into the list, arrows to browse, Tab or `/` to return to
search, Enter to keep a choice in the draft and Esc to cancel. An empty result
does not choose another timezone. Choosing the current value makes no effective
change. Review the diff and confirm Save through the usual configuration flow;
the selector itself never writes a file or restarts a service.

The list includes system local time, UTC, common cities and all 553 reviewed
IANA names/links with region/path identifiers. Top-level abbreviations such as
`EST` are not new choices; a valid existing top-level value is retained only as
the current configuration. The source name/link directory is offline; standard Go `time/tzdata`
provides a rule fallback when system timezone data is missing. A missing rule is
reported and cannot be selected. Offsets use one reference instant per opening,
including half-hour and 45-minute zones. **This is the current offset and it can
change with the date/DST.** Old aliases or custom valid names remain marked as
the current configuration and are not normalized. `Local` follows the process's
existing host environment; it does not infer an SSH client's location or select
China because the menu is Chinese. No host timezone or global `TZ` is changed.

In **Configuration → Notifications → Telegram message language**, choose
**English / 简体中文**. **Telegram and notifications → Set up Telegram** has the
same choice, including first setup. The UI option `--language en` / `--language
zh` is separate: an English menu can send Chinese notifications and a Chinese
menu can send English ones. Missing/empty Telegram language means `en`; only
`en` and `zh` are valid nonempty values. Explicit empty report timezone is
rejected; an omitted timezone retains the existing `Local` default.

The following is a fragment to merge into the existing configuration, not a
replacement file. Keep the existing token-file, chat and enablement settings:

```json
{
  "reports": { "timezone": "Asia/Shanghai" },
  "notifications": { "telegram": { "language": "zh" } }
}
```

After a successful save/apply (or a validated configuration and daemon restart),
new Telegram event, daily-report and explicit test messages use the saved
language. Saving or changing only language sends no test, changes no bot/chat,
and does not isolate recipients, reset cooldowns or resend an archived report.
Queued and in-flight bodies retain their original language and timezone on
retry; an older backlog may still arrive in English. Different language or
event-timezone contexts do not coalesce. Unknown legacy contexts and `Local`
contexts are conservatively kept separate even when their offsets match; a
single offset cannot identify the host's region rules. Webhook keeps its independent English
body and unchanged JSON keys; heartbeat, logs and machine event codes are not
translated. Privacy transformations are applied before both renderers.

New Telegram events show their occurrence time in `reports.timezone`, including
the offset at that event's instant. Database/machine timestamps remain UTC.
Daily reports use their saved document's timezone and period, including each
endpoint's historical offset; they do not acquire the current configuration's
offset or a recalculated period. A historical empty/`Local` timezone that did
not retain a fixed region is explicitly unknown and its saved instants are
shown in UTC, never interpreted through today's host timezone. The billing
section uses its own saved period/timezone and tariff, which can differ from
the report's. Legacy snapshots without full structured
content say that the original complete content is unavailable. Local archives,
HTML and old messages are not rewritten. Scheduling, billing/forecast cycles
and SSH historical hours still share the existing report timezone and coverage
limits. Unknown or partial data never means healthy or zero loss.

The daily summary's coverage describes its saved daily interval, not the whole
billing cycle. Saved cycle counters may understate usage/cost; whole-cycle
completeness is unknown. Zero retained counters do not prove no activity. A
truncated notification retains this uncertainty and the saved tariff's billing
limits; consult the preserved local archive for omitted details.

This source revision adds database **schema 12** only for saved outbox
presentation (`language`, `presentation_timezone`). Old rows default to English
with unknown timezone metadata and keep their exact body bytes. Migration and
backup validation support earlier schemas; older executables reject schema 12.
Verify a standalone compatible backup and retain configuration/keys separately
before using the new binary. Alpha.6 also rejects the added language config
field: a planned rollback needs the matching earlier config and DB backup,
not only old executables. Config/API schema 1 and sensor protocol v5 remain
unchanged. The project retains its conservative **4096 UTF-8 byte** message
budget, with merge reserve and localized truncation notices; this is not
Telegram's documented 4096-character-after-entity-parsing limit. Report summaries
omit complete escaped lines when necessary and reserve a local-archive
truncation notice; they are not split into unbounded messages.

中文操作：本节功能已包含在当前公开版，首次随 alpha.7 公开；alpha.6 安装包及其冻结文档字节不变。
运行 `sudo noderampart setup --language zh` 或 `sudo noderampart tui --language zh`，
进入**功能配置 → 日报 → 报告时区**，搜索“北京”“上海”、英文地名、IANA 名称或
UTC 偏移即可选择，无须手输 IANA。下键进入列表，上下浏览，Tab 或 `/` 返回搜索，
Enter 暂存草稿，Esc 取消；空结果和选择当前值不产生配置变更。仍须验证、差异确认和

时区、全局 `TZ` 或系统时间。省略时区仍默认 `Local`，显式空字符串不合法。

进入**功能配置 → 通知 → Telegram 消息语言**，或**Telegram 与通知 → 设置 Telegram**，
选择 **English / 简体中文**。`notifications.telegram.language` 保存 `en` 或 `zh`，

保存成功后新生成/入队的事件、日报和显式测试采用所选语言；不自动测试、不换凭据或

## Telegram

1. Open the official [BotFather](https://t.me/BotFather), use `/newbot`, and keep
   the resulting token private. See the [Telegram bot tutorial](https://core.telegram.org/bots/tutorial).
2. Start a chat with your bot and send it a message, or add it to the intended
   group and send a message it can receive.
3. Obtain that chat's numeric ID from the `message.chat.id` field of the official
   [getUpdates API](https://core.telegram.org/bots/api#getupdates). A group ID may
   be negative; retain its sign. NodeRampart does not discover the ID automatically.
4. In **Telegram and notifications → Configure**, enter the token and chat ID,
   choose enabled and confirm. Blank token input retains an existing token.
5. Choose **Send a test notification** explicitly, then inspect delivery status.
   Merely saving configuration does not send a test message.

If you have Python 3, this optional local helper prompts for the token without
putting it in shell history or command arguments. It prints only numeric chat
IDs from recent updates; it does not send a message. Run it in a terminal after
sending your bot a message. A bot already using a webhook or another poller may
need its existing application's configuration instead.

```sh
python3 - <<'PY'
import getpass, json, urllib.request
try:
    token = getpass.getpass('Telegram bot token (hidden): ').strip()
    if not token or any(c not in '0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz_:-' for c in token):
        raise ValueError()
    with urllib.request.urlopen('https://api.telegram.org/bot' + token + '/getUpdates?limit=20', timeout=15) as response:
        raw = response.read(65537)
    if len(raw) > 65536:
        raise ValueError()
    data = json.loads(raw)
    ids = {item['message']['chat']['id'] for item in data.get('result', []) if 'message' in item}
    print('Chat IDs:', ', '.join(str(value) for value in sorted(ids) if type(value) is int) or 'none; send the bot a message first')
except Exception:
    print('Could not read chat IDs; check the token, network and existing bot integration. No token was printed.')
PY
```

Token files created by setup are mode 0600 and readable only by the daemon
identity and root. They are excluded from ordinary database backups. Disabling
delivery retains the local credential; ordinary uninstall retains it too.
If a token was exposed elsewhere, revoke/replace it through BotFather and update
the local setting. Repeated alerts can be merged or silenced without disabling
event recording. See [notification behavior](V0.3_OPERATIONS.md#coalescing-and-silences).

Telegram 配置使用您自己的 BotFather token 和目标 chat ID。token 输入隐藏，保存配置
不会自动发送测试消息；测试发送是独立操作。停用通知或普通卸载会保留本地凭据。

Use a nonzero numeric chat ID, not a mutable `@username`. Each queued body is
bound to the public bot number and chat ID through a credential-free target
hash. Changing bot/chat or tightening notification IP privacy retains older
unsent bodies in isolation. Hand-edited configuration, restored databases and
restarts apply the same policy. Same-target token rotation retains retries and
cooldowns; disabling a known same target pauses delivery. An unknown identity
is isolated and is never automatically adopted when credentials recover.

Inspect **Notification messages** or `noderampart notify list`. Keep the isolated
bodies, or explicitly use **Discard isolated notification bodies** /
`noderampart notify discard-isolated` to erase only their retained text. This
preserves the current target's queue and sent history. Individual retry and
destination resume cannot migrate isolated bodies. A request already in flight
may finish at its original receiver. Unsent isolation follows the normal
seven-day message expiry; the queue status's `isolated` count is a subset of
retained unsent messages, not proof that they are eligible for delivery.

请填写非零数字 Chat ID，不能使用可变的 `@username`。队列使用公开 Bot 数字 ID
和 Chat ID 派生不含凭据的目标摘要；更换 Bot/Chat、收紧通知 IP 隐私、手改配置、
恢复数据库和重启均执行同样的隔离策略。同目标换 Token 保留重试与限流；停用
已确认同目标只暂停投递。归属未知的消息不会在凭据恢复后自动绑定新目标。
可保留隔离正文，或在菜单显式选择“丢弃隔离通知正文”；也可运行
`noderampart notify discard-isolated`。此操作保留当前目标队列和已发送历史，
单条重试或恢复限流不会迁移隔离正文。已在发送中的请求可能在原目标完成；
隔离的未发送消息仍遵循七天到期规则。

## Local GeoIP

GeoIP is optional. Without it, traffic and SSH observation continue; country,
city and ASN information is unavailable. Lookups with installed MMDB databases
are local and approximate.

Create your own [GeoLite account](https://www.maxmind.com/en/geolite2/signup),
enroll for the databases and accept the applicable
[MaxMind terms](https://www.maxmind.com/en/geolite/eula). Obtain an Account ID and
License Key from your account. NodeRampart cannot register or accept terms for
you, and the project does not redistribute GeoLite databases.

In **Local GeoIP databases → Download and configure**, enter those credentials,
confirm your own terms acceptance and choose whether to enable daily updates.
Both City and ASN downloads must pass validation before their paths are
activated. A failed download leaves the previous valid configuration in place.
The menu shows database build dates, last update results and update scheduling.
Credentials are saved in root-only `/etc/noderampart/maxmind.credentials.json`;
databases and their license notices are under `/etc/noderampart/geoip`.

Downloads, MMDB staging and publication stream through bounded buffers. The
complete upstream MMDB `Verify()` runs in a fixed child of the installed CLI,
using only an inherited read-only descriptor. When started as root, that child
drops to `nobody`, clears supplementary groups and denies new privileges before
parsing data; publication still requires the administrative parent. Validation
has a 45-second wall deadline, 30-second CPU limit and a hard additional virtual
address-space budget of 1 GiB over Go's startup reservation. The 512 MiB Go heap
limit is soft; neither that setting nor the address-space budget is an RSS
guarantee. Existing 160 MiB database, archive and structure limits remain in
force. Cancellation or any validation/resource failure keeps the old generation.
The validated SHA-256 digest is checked again during publication.

Daily updates are opt-in and run through the local
`noderampart-geoip-update.timer`/`.service`. They download data, not executable
code. You can change the schedule choice in the GeoIP menu. After successful
activation, superseded managed databases are removed; this is not a permanent
database archive. Follow [MaxMind's update guidance](https://dev.maxmind.com/geoip/updating-databases/)
and your license's requirements.

Scheduling creates `/etc/tmpfiles.d/noderampart-management.conf` so systemd
recreates the root-only management lock after a reboot, before the updater runs.

```sh
# Refresh after credentials were configured successfully.
sudo noderampart assets update
sudo systemctl status noderampart-geoip-update.timer
sudo journalctl -u noderampart-geoip-update.service --since today
```

You can also select already licensed local City/ASN MMDB files in configuration.
Ensure the daemon can read them through their parent directories; unsupported
permissions or invalid database types are rejected. The automatic updater
manages only the files it created.

GeoIP 需要您自己的 MaxMind 账号、许可确认及下载凭据，可跳过。安装后查询走本地库，
每日更新需主动开启；下载失败保留旧库。请在菜单中检查库龄与更新结果。
下载、解包和发布采用有界流式缓冲。完整 MMDB 校验在固定子进程中执行，root 父进程启动
的校验子进程在解析前降权到 nobody、清除附加组并禁止获得新权限，仅持有已固定的只读输入
描述符；特权父进程负责安全发布。校验限制为 45 秒墙钟、30 秒 CPU，以及 Go 启动虚拟地址
预留之外最多增加 1 GiB；512 MiB Go 堆限制属于软限制，不能当作硬 RSS 保证。原有文件与
格式边界保持有效，发布时再次核对校验摘要；取消或资源/校验失败保留旧 generation。

## Egress estimates

Choose **Cloud egress cost estimates** to fetch AWS or OCI public tariffs. The
menu lists available AWS regions and OCI geographic pricing groups; select the
location that matches your deployment. No cloud credentials are requested.
Fetching and activating a tariff also selects that billing profile for future
reports. Both cached provider scenarios can be inspected afterwards.

Sources are the [AWS Price List API](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/using-the-aws-price-list-bulk-api-fetching-price-list-files-manually.html)
and [Oracle's public pricing service](https://docs.oracle.com/en-us/iaas/Content/Billing/Tasks/signingup_topic-Estimating_Costs.htm).
Tariffs are fetched on request, not continuously. The cache shows source,
publication/effective time when supplied, retrieval time and digest. A failed
fetch retains previous cached prices; cache older than seven days is marked
stale. A successful profile activation followed by a cache-write failure is
reported as a partial result so you can inspect the active configuration.

The estimate applies marginal price tiers to observed outbound bytes for the
current fixed monthly cycle in the report timezone. Set
`billing.cycle_start_day` to 1–28 (default 1) in **Configuration → Egress estimates
→ Monthly cycle start day**. Usage, free allowance, budget thresholds and forecast
all use that cycle. It uses this host's assigned cycle free allowance before
charging paid tiers. Assign only the share available to this
host after other hosts/services; default **0** avoids assigning a shared account
allowance to every machine. Enter a whole-cycle allocation, not that allocation
minus this host's already observed usage.

The displayed calculation assumption defaults to **1,073,741,824 bytes per GB**;
you can choose **1,000,000,000**. This is an explicit estimate input, not a claim
that the provider's actual meter has been independently verified. Existing
custom profiles without a byte-unit field retain decimal GB behavior.

The estimate covers **public Internet egress only**. It excludes instance, CPU,
memory, disk, NAT Gateway, inter-zone services, taxes, discounts and other bill
items. Guest TX can include private traffic or overlapping interfaces. Monthly
usage is based on overlapping stored UTC hours; boundaries and coverage gaps
limit precision. Always inspect usage and coverage beside the price.

费用页面只估算公网出站流量，不能当作 AWS/OCI 最终账单。免费额度可能在多个服务和
主机之间共享；请输入分给本机的整个结算周期额度，默认 0。在“功能配置 → 出站费用估算
→ 每月结算起始日”设置 `billing.cycle_start_day`（1–28，默认 1），使用报告时区；
用量、免费额度、预算阈值与预测采用同一周期。价格缓存、GB 换算假设、观测流量和
覆盖情况都会影响结果；实例、CPU、内存、磁盘等费用不在范围内。

## Upgrades and removal

Before upgrading, create and verify a consistent database backup from **Backup,
replay and privacy**, and retain the previous program version. Database backups
do not contain Telegram/MaxMind credentials or all managed configuration. Keep
any separately required configuration/secret backup under your own restricted
backup policy; do not attach it to public issues.

Use the native package manager, the maintained default-latest entry, or a frozen
Release bootstrap with an explicit intended `--version`.
Existing configuration is retained, and upgrades preserve disabled and masked
service choices. The v0.4 management additions retain configuration/API schema 1
and use database schema 14. Schema 12 introduced presentation metadata, schema 13
added native channels, and schema 14 adds official-account intents and budgets.
Durable budget/health state and the retention ledger
remain additive; public schema 7 journal recovery is preserved, and schema 8 isolates
notification targets and uncertain legacy backlog. See [alerts and evidence](ALERTS_EVIDENCE.md) for configuration and
export commands. New daily archives retain bounded pricing inputs;
older reports keep an empty pricing snapshot. Back up before upgrading: a
pre-schema-11 binary refuses this database and configuration recovery does not
downgrade it. A billing profile's new optional byte-unit field can be
incompatible with old binaries; do not assume that an older executable can use
new configuration or data. Restore a verified matching backup to a new path
when doing a planned downgrade; recovery never automatically downgrades a DB.

For a source-to-package transition, use the reviewed checkout:

```sh
sudo ./scripts/source-to-package.sh --prepare
# Then install the selected native package using apt or dnf, as above.
sudo /usr/bin/noderampart setup
```

The preparation validates the fixed ownership allowlist before stopping and
removing source-owned files. New source installs record six hashes in
`/usr/local/share/doc/noderampart/source-install.manifest`: the three
`/usr/local/bin/noderampart{,d,-sensor}` binaries, two
`/etc/systemd/system/noderampart{d,-sensor}.service` units and
`/usr/local/libexec/noderampart/manage-remove`. Older five-file manifests are
accepted and remove only their five recorded files; an unrecorded helper is
left untouched. Reconcile any existing helper's ownership before the transition:
alpha.9 native package pre-install refuses a remaining source helper, including a
dangling symlink; published alpha.8 did not check this helper-only case. A verified sixth
entry permits its removal. Pre-manifest installations require the exact retained
original build with `--legacy-checkout /absolute/original/build`.
Modified or unowned files require manual reconciliation. Data and administrator
drop-ins remain. The old source-path GeoIP timer is removed during transition;
re-enable daily updates in the native installation's menu if desired.

RPM 6 can run implicit `%sysusers` before `%pre`. Published alpha.9 therefore
checks these pre-existing conflicts in an embedded Lua `%pretrans` before
package-controlled account creation, then repeats the checks in `%pre` as
defense in depth. The early guard also checks managed directory/configuration
types and the two full service-unit overrides. Only those unit paths may be
direct `/dev/null` masks; a helper pointing to `/dev/null` still conflicts.
The guard neither removes unowned files nor prevents concurrent local path
changes between transaction phases. Sysusers declarations and service
identities remain unchanged. Published alpha.8 packages are unchanged.

源码安装的所有权记录固定为六项：三个 `/usr/local/bin` 程序、两个 `/etc/systemd/system`
服务单元及已安装的 `manage-remove` helper。旧五项记录继续兼容，只删除已记录的五项，
不删除未记录的 helper。执行转换前先核对既有 helper 的所有权：残留的源码 helper 会使
alpha.9 原生包 pre-install 拒绝，包括悬空链接；已发布 alpha.8 未检查仅残留 helper
的情形。有原始可核验的第六项才能删除，不能按文件名推断。无 manifest 时必须
提供原始构建的 `--legacy-checkout`。验证通过后才停止/删除固定源码文件，保留数据和
管理员 drop-in；不是任意目录卸载器。

RPM 6 的隐式 `%sysusers` 可以先于 `%pre` 执行。公开 alpha.9 包含
嵌入式 Lua `%pretrans`，在本包创建账户前只读检查既有冲突，保留 `%pre` 后续
复核。检查包括目录、配置类型及两个完整服务单元覆盖；仅这两个单元路径允许
直接指向 `/dev/null` 的管理员 mask，helper 的同类链接仍拒绝。不自动删除
无归属文件，不保证抵御阶段之间的并发路径修改；sysusers 声明、服务身份和
已发布 alpha.8 字节均不变。

**Services and uninstall** offers two distinct operations:

| Operation | What remains |
| --- | --- |
| Uninstall, keep configuration and data | Configuration, credentials, database, GeoIP data and pricing cache remain for reuse. |
| Uninstall and delete all managed data | Deletes fixed `/etc/noderampart`, `/var/lib/noderampart`, `/var/cache/noderampart` trees and service accounts, after safety checks. |

The same operations use a locally installed helper, even offline:

```sh
# Native DEB/RPM installation:
sudo /usr/libexec/noderampart/manage-remove

# Source installation (choose this path only for a source install):
sudo /usr/local/libexec/noderampart/manage-remove
```

Add **`--purge`** only when you intend to delete the fixed managed data trees.
These trees may contain backups as well as active history. The helper stops
observation and the owned GeoIP timer, then uses the appropriate removal method;
system dependencies and other administrator drop-ins are retained. Both removal
choices delete the fixed managed tmpfiles rule above, preserve other tmpfiles
rules and leave the current runtime lock inode in place. Purge refuses
symlinked directories and mounts/nested mounts before deletion. It never follows
arbitrary configuration paths to delete external files.

RPM can retain an edited package configuration as `config.json.rpmsave`.
Reinstalling does not restore it automatically: review and reconcile that file
yourself. Default-preserving removal retains files without promising automatic
activation of old settings. If removal failed after the package was removed,
remaining files are not evidence of successful purge; inspect the error and
reinstall the reviewed package if you need its local helper again.

普通卸载保留配置、凭据、历史和缓存；彻底卸载需单独选择，并删除三个固定应用目录。
目录内的备份也会被删除。卸载不会删除系统依赖，也不会按配置中任意路径寻找数据删除。

## Strict local diagnosis and textfile monitoring

`status` and `doctor` return JSON on stdout; errors go to stderr. Doctor includes
`overall`, stable `reason_code`, impact and next step for each check. It never
repairs automatically. The default doctor exit behavior remains unchanged;
`--strict` opts into 0=required checks normal, 1=confirmed degradation,
2=diagnostics/configuration unavailable or unknown. Disabled/not-applicable
checks are not failures; unknown is not healthy. A started process and a quiet
SSH journal do not prove full detection readiness; a cold authentication window
can remain unknown while base monitoring is ready.

```sh
sudo noderampart status
sudo noderampart doctor --strict
```

For read-only orphan diagnosis on an independently established standalone
historical database copy, use `doctor --foreign-keys-snapshot` as described in
[Storage budget](STORAGE-BUDGET.md). Stop every database user and preserve the
original database and all sidecars as private forensic evidence first. Do not
remove an unresolved journal merely to make that check run. This check neither
migrates/repairs the copy nor certifies live monitoring.

Manual textfile export opens no port and installs no node_exporter, timer or
service. Use a private parent and a file owned by the publishing UID; root
exports therefore need a root-created directory:

```sh
DIAG_DIR=$(sudo mktemp -d)
sudo noderampart metrics export --output "$DIAG_DIR/noderampart.prom"
sudo cat "$DIAG_DIR/noderampart.prom"
```

The file is atomically published, initially 0600. A retained safe 0600/0640
file owned by the same publisher keeps its mode/group on replacement. Arrange
read/execute access for your existing collector explicitly, without shared
write permission or symlink paths; a collector cannot read a root-only 0700
example directory automatically. Run export manually or with an existing local
scheduler. Labels are limited to fixed component names, never IPs, event IDs,
arbitrary errors or credential URLs. Check `noderampart_collection_success`,
`noderampart_health_state` (0 healthy, 1 degraded, 2 unknown), generation time and
`noderampart_export_valid_until_timestamp_seconds`, which expires after five
minutes. A failed collection publishes a fresh failure marker and returns an
error; unsafe/unwritable output may prevent replacement, so consumers must
reject expired files even if the old value claimed healthy.

`status`/`doctor` 的 stdout 为 JSON，错误写 stderr；doctor 给出总体状态、稳定原因码、
影响和下一步，不自动修复。默认退出语义保持兼容，显式 `--strict` 才使用
0=所需检查正常、1=确认异常/降级、2=配置/诊断失败或未知。禁用/不适用不算异常，
未知不算健康；进程已启动或 SSH 日志静默不代表检测完全就绪，冷启动观察窗口可能
未知而基础监控已就绪。历史孤儿只读检查的副本/sidecar 前提见存储文档，不可丢弃
未决 journal 来绕过拒绝。

textfile 不开端口、不安装 node_exporter/timer/service，默认手工或既有调度调用。
输出父目录与文件须按发布 UID 管理；root 导出先用上述 `sudo mktemp -d`。
新文件原子发布为 0600，同发布者的安全 0600/0640 文件替换时保留权限/组；为现有
读取器明确安排只读/目录进入权限，不开放共享写入、不走 symlink。标签只有固定维度。
读取方同时检查 collection_success、health_state、生成时间及五分钟 valid_until；
采集失败会发布失败标记，发布本身失败时旧文件可能保留，不能用过期旧值显示当前健康。

## Complete local reports, trends and forecast

New daily snapshots contain a structured full document independently of the
short, source-free Telegram/Webhook summary. Local text/HTML uses that full body;
JSON also carries the structured summary, coverage, pricing and notes. HTML is
static, self-contained and escaped, with no external scripts or CDN. These are
bounded retained observations, not unlimited history: generation has a 20-second
budget, full body is at most 128 KiB, JSON document at most 256 KiB, attribution
uses `top_n` (at most 50), and displayed coverage segments/gaps are at most 100.
Exceeding a hard limit fails rather than presenting a silently truncated complete
report. Archives retain their original privacy-transformed identities when
configuration changes; old history is not rewritten. Local report files can
contain linkable history and need private permissions; review before sharing.

Choose a retained date from `report list`. Export writes stdout, not an
`--output` file; these shell redirections create private local files:

```sh
umask 077
REPORT_DIR=$(mktemp -d)
sudo noderampart report list
REPORT_DATE=2026-09-29 # Replace with an actually retained date.
sudo noderampart report export --date "$REPORT_DATE" --format html > "$REPORT_DIR/report.html"
sudo noderampart report export --date "$REPORT_DATE" --format json > "$REPORT_DIR/report.json"
sudo noderampart report trend --days 7 > "$REPORT_DIR/trend-7.json"
sudo noderampart report trend --days 30 > "$REPORT_DIR/trend-30.json"
sudo noderampart report forecast > "$REPORT_DIR/forecast.json"
```

Flags including `--config /absolute/config.json` go after the command/subcommand.
`report show --date DATE --format text` and the Reports menu reuse existing
archives. `report now` creates a partial current-day snapshot only when none is
retained; immutable snapshots are never overwritten later. A legacy short
snapshot is exported with its original body and an explicit full-content-unavailable
notice, never reconstructed as an original complete report. Trend covers the
preceding 7 or 30 completed local civil dates, excluding today; `state` separates
complete, partial, missing and pruned, with null missing totals. Original matching
full snapshots take precedence; otherwise retained aggregates are labelled as
such. UTC-hour buckets can over-include non-hour timezone boundaries, and DST
changes civil-day length. Neither absence of a gap row nor a total of zero
proves complete coverage.

Forecast uses the current fixed monthly cycle described in **Egress estimates**.
It needs complete current-cycle interface coverage and all days complete in each
available 7/30-day scenario. Output includes byte rate, projected cycle-end usage,
configured-tariff cost, and byte/cost threshold dates; a missing crossing date is
null. Scenario minimum/maximum are simple extrapolations, not confidence
intervals. Zero rate has no future crossing; missing/partial/pruned history is
not filled with zero and can make prediction unavailable. Guest TX is not a bill,
and fees outside the selected model are excluded. Changing cycle/timezone can

## Sensor commit watermarks

Protocol v5 identifies each session/interface batch by sequence. Its ACK names
collector-health and traffic writes committed atomically with the durable
watermark. Events and each notification channel's outbox decisions have separate
transactions and explicit flags; pending/rejected work leaves an immutable partial
ACK even if a later retry finishes. `complete` concerns local processing only,
never Telegram/Webhook receipt. Socket writes and frame reads are not commit
success. Cumulative collector-health snapshots prevent repeating already committed
counts after ACK loss; duplicate batches do not repeat accounted traffic/health.

In published alpha.9, `status.sensor_receipts` adds the bounded
session/sequence identity associated with each `sensor_interfaces` timestamp.
Diagnosis first matches session, interface and exact sequence, then compares
`UnixMicro()` values, which is the on-disk `sent_at_us` precision. Nanosecond
remainders of the same committed observation no longer cause
`sensor_commit_unavailable`. This is exact persisted-unit equality, not a 1µs
grace period. A new receipt even in the same microsecond cannot inherit an old
commit. Unsequenced/legacy or absent identities remain unknown; the latest
partial watermark remains degraded. Reading status across concurrent
sequence advancement can still yield unknown; a newer sequence can have gaps
and cannot retroactively certify an earlier receipt. This fixes neither every
unknown nor historical alpha.8 results. Install matching CLI/daemon binaries:
older status omits identity, so a new CLI conservatively reports unknown.
No DB/protocol/config/API version or durable ACK transaction changes are needed.

精确序号，再按 sent_at_us 的 UnixMicro 精度比较同一观察；不使用 1 微秒容差。

## Fixed HTTPS heartbeat and Webhook

Both features default to disabled. Configure them in the Notifications group or
in the existing JSON file, then use the normal validated save/restart path.
`heartbeat` requires `enabled`, `endpoint`, `instance_id`, `credential_file`,
`interval` (1m–24h, default5m) and `timeout` (1s–30s). The endpoint must be fixed
HTTPS without URL credentials, query or fragment. A protected regular0600 file
contains a20–512-byte bearer; no token enters SQLite, report exports or errors.
The operator provisions this file for the daemon identity; it is never included
in database backups. No new listener, timer or external receiver is installed.

Heartbeat JSON contains only instance identifier, UTC time, version,
`process_alive`, `functional_health` (healthy/degraded/unknown) and fixed reason
codes. The external receiver detects missed heartbeats. Each worker attempt
uses fresh status; at most one retry occurs after1s for transient failures. Permanent failures and rate limits do not get an immediate retry; Retry-After extends the next wait and an unbounded server hold requires restart. Otherwise the worker waits for the configured
interval. It cannot accumulate a durable queue or block collection. HTTP failure
is optional degradation; a live process can have degraded monitoring. Correct a
missing local resource and explicitly restart. Redirects are refused.

`notifications.webhook` requires `enabled`, `endpoint`, a non-secret
`receiver_id` (1–64 bytes), `credential_file` and `timeout` (1s–30s). It shares the
existing event/report outbox, admission bounds, global silences, privacy,
cooldowns, retries and isolation. JSON schema1 includes stable `message_id`,
optional `event_id` and `body` (the existing formatted notification body).
Receivers may deduplicate by message ID; exactly-once delivery is not promised.
Responses are read up to64KiB;4xx permanent failures are quarantined except
408/429, and bounded Retry-After handling persists a destination cooldown.
Redirects never send credentials to another target.

Changing endpoint or receiver identity isolates old unsent work. Unlike Telegram
bot/chat rotation, a Webhook credential may select another tenant at the same
URL: changing its non-secret file generation conservatively isolates old work.
Restart with the same file/target retains the target. Disabling/re-enabling it
pauses/resumes only that same known target. Stricter notification privacy also
isolates older immutable bodies. The menu offers retention by default and an
explicit selected-channel discard; no migration of old bodies is implemented.

```sh
# Explicitly queues a message; use only after choosing your own test receiver.
noderampart notify test --channel webhook
noderampart notify status
# Explicit destructive handling of isolated bodies only, after inspection.
noderampart notify discard-isolated --channel webhook
```

HTTPS 心跳与通用 Webhook 均默认关闭，使用现有通知配置组或 JSON 配置及正常验证、
保存、重启流程。心跳需固定 HTTPS `endpoint`、非秘密 `instance_id`、受保护的
`credential_file`、1m–24h间隔（默认5m）及1s–30s超时；Webhook 需固定 HTTPS、

的0600普通文件读取，操作员按daemon身份部署；不入数据库、备份、报告或错误信息。
拒绝重定向，不新增端口、接收中心、服务或timer。

心跳只含实例标识、UTC时间、版本、进程存活与功能 healthy/degraded/unknown 摘要
及固定原因码，由外部接收方判断失联。最多间隔1秒重试一次，此后等待配置间隔；
每次读取新状态，不持久积压、不阻塞采集。永久失败或限流不立即重试；Retry-After延长等待，无界目标暂停须重启后再尝试。进程存活不表示功能健康，外发失败只令
可选功能降级；修复缺失本地资源后明确重启。

Webhook复用发件队列、全局静默、隐私、限流、重试和隔离，JSON schema1包含稳定
message_id、可选event_id及现有格式化通知body。接收方可据ID去重，但不承诺恰好一次。
