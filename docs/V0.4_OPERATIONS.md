# Installation and everyday management / 安装与日常管理

Start with [English README](../README.md) or [中文 README](../README.zh-CN.md)
for a short introduction and the menu walkthrough. This guide explains local
installation, optional accounts, recovery and removal for **v0.4.0-alpha.2**.

The source repository is public. The first installation-package release,
`v0.4.0-alpha.2`, is being prepared as a draft; its download commands become
usable only after that release is published. Draft asset access by a maintainer
is not public download availability. No release is published by a local build.

源码仓库已公开，首次安装包 `v0.4.0-alpha.2` 正在准备为草稿；只有同一 Release
发布后，固定版本下载命令才可公开使用。维护者能读取草稿不代表公众可以下载。
当前可使用经过检查的本地源码或安装包，安装命令仅在您管理的服务器上执行。

## Local installation before publication

For an ordinary server, prefer a native package supplied by a trusted build.
The server needs systemd and root access. Choose the package for its distribution
and architecture; `uname -m` reports `x86_64` or `aarch64` on the targeted systems.
Debian calls these architectures `amd64` and `arm64`.

Debian 12/13, amd64 example, from the directory containing the reviewed package:

```sh
sudo apt update
sudo apt install ./noderampart_0.4.0-alpha.2_amd64.deb
sudo noderampart setup
```

Fedora 44, x86_64 example:

```sh
sudo dnf install ./noderampart-0.4.0-0.alpha.3.fc44.x86_64.rpm
sudo noderampart setup
```

For Fedora 43 use the `fc43` package; for ARM64 use `_arm64.deb` or `.aarch64.rpm`.
apt/dnf install declared dependencies. Keep repository signature checks enabled.
If local policy requires signed RPMs, obtain an appropriately signed package;
the bootstrap does not override that policy.

**A fresh Debian package enables and starts observation with safe defaults,
subject to system service policy. Fedora follows its service presets.** Telegram
is disabled and GeoIP/price downloads are optional. The setup menu's Start action
explicitly enables the services using the configuration you have chosen.

原生安装包会自动处理依赖。Debian 首次安装会按系统策略启用服务并以默认配置开始
观察，Fedora 遵循 preset；TUI 中的“启动已配置服务”用于确认启用您选定的配置。
已有安装升级时保留启用、禁用和 mask 状态。

### Building a package yourself

Run builds without root from the repository root, using Go 1.25 or newer and
make. The Release workflow pins Go 1.26.8 for Debian and SBOM inspection;
Fedora builds use the distribution Go toolchain with `GOTOOLCHAIN=local`,
recorded in each package buildinfo. Download dependencies on the build machine; the resulting server package
does not require Go. Debian packaging additionally needs `dpkg-deb`; Fedora
packaging needs Python 3, `rpm-build`, `systemd-rpm-macros` and the spec's build dependencies.
Use a Fedora 43 or 44 build environment to produce that distribution's RPM.

```sh
# Debian artifact: dist/noderampart_0.4.0-alpha.2_amd64.deb
export COMMIT=$(git rev-parse HEAD)
export BUILD_DATE=$(git show -s --format=%cI "$COMMIT")
./scripts/build-release.sh --deb amd64

# Fedora artifact: dist/rpm/noderampart-0.4.0-0.alpha.3.fc44.x86_64.rpm
# Run this command in a Fedora 44 build environment.
./scripts/build-release.sh --rpm amd64
```

Use `arm64` in place of `amd64` for the other target. Cross-compilation and
metadata checks do not prove that the program has run on real ARM64 hardware.
See [development validation](DEVELOPMENT.md) before distributing a build.

For a source installation, build binaries and use the source installer instead:

```sh
make build
sudo ./scripts/install.sh
sudo /usr/local/bin/noderampart setup
```

Repeating a source installation preserves each service's enabled and running state. A permanent mask occupies the source unit file path, so installation refuses it before making changes; runtime masks remain in place.

The source installer requires existing system utilities including systemd and
user/group administration commands. Native packages are the automatic dependency
installation path. Source installations use `/usr/local/bin`; native packages
use `/usr/bin`. Do not install both over one another.

### The published bootstrap

After publication, the fixed-version bootstrap downloads the corresponding
package and `SHA256SUMS` from the official GitHub release. Downloads have size,
time and redirect limits; the package's name, version and architecture must also
match. HTTPS and a checksum from the same release establish content consistency,
not an independent author signature. The draft release workflow also prepares
[GitHub build attestations](https://docs.github.com/en/actions/how-tos/secure-your-work/use-artifact-attestations).

The [README download-first example](../README.md#install-in-one-command--after-a-matching-package-release) saves `bootstrap.sh` for inspection before a separate `sudo sh` command.
Bootstrap does not run attestation verification; follow [the package and provenance checks](RELEASE_VERIFICATION.md#download-and-verify) yourself. It has no `--dry-run` option.
Its supported options are `--version v0.4.0-alpha.2`, `--no-setup` and the equivalent
`--non-interactive`. It never selects `latest` or silently downgrades a package.
If the release is missing, it exits with an error. Some missing system download
dependencies may have been installed before that failure.

The default path requires a controlling terminal. It opens `/dev/tty` after
installation, so configuration input is independent of the downloaded script
pipe. Do not use `sudo -S` with that pipe. For automation, pass `--no-setup`, then
open `sudo noderampart setup` in a terminal later. This flag skips the menu; it
does not change the native package's initial service policy.

## Configuration and recovery

Open `sudo noderampart setup` for onboarding or `sudo noderampart tui` for the main
menu. Use `--language en` or `--language zh` after the subcommand to choose a
language. An SSH session needs a terminal, for example an existing interactive
SSH login or `ssh -t` with your own destination.

Use **Configuration** to edit grouped fields. Review shows each effective old → new value in a scrollable page before final confirmation; reverting a field to its original value removes it from the diff. Changes remain a draft until you
validate, review and confirm Save. Escape/back lets you discard the draft. The
menu checks the whole configuration, preserves advanced fields and rejects a
save if another process edited the file after it was loaded.

The managed file is **`/etc/noderampart/config.json`**. This is also the path used
by the installed daemon, sensor and optional GeoIP timer. Management commands
reject an alternate config path. Existing noninteractive CLI commands still
accept `--config`; operating another configuration requires coordinating the
service units manually.

配置菜单覆盖接口、SSH、阈值、通知、日报、GeoIP、隐私、价格、存储及高级路径设置。
修改先保存在草稿里，验证并确认后才写入固定配置文件。改变数据库路径不会搬迁历史数据，
改变接口可能导致短暂采集中断；先查看健康记录，再判断某一时段是否完整。

| Choice | Practical guidance |
| --- | --- |
| Interfaces | Leave both selections empty to follow IPv4/IPv6 default routes. Select explicit names for policy routing or unusual networks. Avoid monitoring overlapping bridge/tunnel paths when comparing totals. |
| Thresholds | Inspect normal usage first. Thresholds apply per interface; tune for your actual traffic. |
| Reports | Choose your timezone and daily time. Historical backfill can generate reports from stored observations, but cannot recreate missing collection. |
| Privacy | Prefix storage is the default. Hash mode needs a persistent key; changing keys prevents historical identity comparisons. |
| Storage and paths | Database paths stay under `/var/lib/noderampart`; sockets stay under `/run/noderampart`. The menu does not migrate a database or weaken the service sandbox. |

Saving restarts the affected running services as required while retaining
disabled or masked states. A failed activation attempts to restore the prior
configuration and service state. If interrupted, use **Services and uninstall →
Recover previous configuration** before further edits. Recovery reports
conflicts instead of replacing a file changed by another administrator. It does
not downgrade a database.

For a manual edit, validate before an intentional restart:

```sh
sudo noderampart config test
sudo systemctl restart noderampartd.service noderampart-sensor.service
sudo noderampart doctor
sudo noderampart status
```

That explicit restart starts stopped services; use the TUI save operation if you
want its service-state preservation. If status cannot connect, inspect
`sudo systemctl status noderampartd.service noderampart-sensor.service` and the
local journal. Do not delete the management lock to bypass an active operation.

## Telegram

1. Open the official [BotFather](https://t.me/BotFather), use `/newbot`, and keep
   the resulting token private. See the [Telegram bot tutorial](https://core.telegram.org/bots/tutorial).
2. Start a chat with your bot and send it a message, or add it to the intended
   group and send a message it can receive.
3. Obtain that chat's numeric ID from the `message.chat.id` field of the official
   [getUpdates API](https://core.telegram.org/bots/api#getupdates). A group ID may
   be negative; retain its sign. NodeRampart does not discover the ID automatically.
4. In **Telegram and notifications → Configure**, enter the token and chat ID,
   choose enabled and confirm. Blank token input retains an existing token.
5. Choose **Send a test notification** explicitly, then inspect delivery status.
   Merely saving configuration does not send a test message.

If you have Python 3, this optional local helper prompts for the token without
putting it in shell history or command arguments. It prints only numeric chat
IDs from recent updates; it does not send a message. Run it in a terminal after
sending your bot a message. A bot already using a webhook or another poller may
need its existing application's configuration instead.

```sh
python3 - <<'PY'
import getpass, json, urllib.request
try:
    token = getpass.getpass('Telegram bot token (hidden): ').strip()
    if not token or any(c not in '0123456789ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz_:-' for c in token):
        raise ValueError()
    with urllib.request.urlopen('https://api.telegram.org/bot' + token + '/getUpdates?limit=20', timeout=15) as response:
        raw = response.read(65537)
    if len(raw) > 65536:
        raise ValueError()
    data = json.loads(raw)
    ids = {item['message']['chat']['id'] for item in data.get('result', []) if 'message' in item}
    print('Chat IDs:', ', '.join(str(value) for value in sorted(ids) if type(value) is int) or 'none; send the bot a message first')
except Exception:
    print('Could not read chat IDs; check the token, network and existing bot integration. No token was printed.')
PY
```

Token files created by setup are mode 0600 and readable only by the daemon
identity and root. They are excluded from ordinary database backups. Disabling
delivery retains the local credential; ordinary uninstall retains it too.
If a token was exposed elsewhere, revoke/replace it through BotFather and update
the local setting. Repeated alerts can be merged or silenced without disabling
event recording. See [notification behavior](V0.3_OPERATIONS.md#coalescing-and-silences).

Telegram 配置使用您自己的 BotFather token 和目标 chat ID。token 输入隐藏，保存配置
不会自动发送测试消息；测试发送是独立操作。停用通知或普通卸载会保留本地凭据。

## Local GeoIP

GeoIP is optional. Without it, traffic and SSH observation continue; country,
city and ASN information is unavailable. Lookups with installed MMDB databases
are local and approximate.

Create your own [GeoLite account](https://www.maxmind.com/en/geolite2/signup),
enroll for the databases and accept the applicable
[MaxMind terms](https://www.maxmind.com/en/geolite/eula). Obtain an Account ID and
License Key from your account. NodeRampart cannot register or accept terms for
you, and the project does not redistribute GeoLite databases.

In **Local GeoIP databases → Download and configure**, enter those credentials,
confirm your own terms acceptance and choose whether to enable daily updates.
Both City and ASN downloads must pass validation before their paths are
activated. A failed download leaves the previous valid configuration in place.
The menu shows database build dates, last update results and update scheduling.
Credentials are saved in root-only `/etc/noderampart/maxmind.credentials.json`;
databases and their license notices are under `/etc/noderampart/geoip`.

Daily updates are opt-in and run through the local
`noderampart-geoip-update.timer`/`.service`. They download data, not executable
code. You can change the schedule choice in the GeoIP menu. After successful
activation, superseded managed databases are removed; this is not a permanent
database archive. Follow [MaxMind's update guidance](https://dev.maxmind.com/geoip/updating-databases/)
and your license's requirements.

Scheduling creates `/etc/tmpfiles.d/noderampart-management.conf` so systemd
recreates the root-only management lock after a reboot, before the updater runs.

```sh
# Refresh after credentials were configured successfully.
sudo noderampart assets update
sudo systemctl status noderampart-geoip-update.timer
sudo journalctl -u noderampart-geoip-update.service --since today
```

You can also select already licensed local City/ASN MMDB files in configuration.
Ensure the daemon can read them through their parent directories; unsupported
permissions or invalid database types are rejected. The automatic updater
manages only the files it created.

GeoIP 需要您自己的 MaxMind 账号、许可确认及下载凭据，可跳过。安装后查询走本地库，
每日更新需主动开启；下载失败保留旧库。请在菜单中检查库龄与更新结果。

## Egress estimates

Choose **Cloud egress cost estimates** to fetch AWS or OCI public tariffs. The
menu lists available AWS regions and OCI geographic pricing groups; select the
location that matches your deployment. No cloud credentials are requested.
Fetching and activating a tariff also selects that billing profile for future
reports. Both cached provider scenarios can be inspected afterwards.

Sources are the [AWS Price List API](https://docs.aws.amazon.com/awsaccountbilling/latest/aboutv2/using-the-aws-price-list-bulk-api-fetching-price-list-files-manually.html)
and [Oracle's public pricing service](https://docs.oracle.com/en-us/iaas/Content/Billing/Tasks/signingup_topic-Estimating_Costs.htm).
Tariffs are fetched on request, not continuously. The cache shows source,
publication/effective time when supplied, retrieval time and digest. A failed
fetch retains previous cached prices; cache older than seven days is marked
stale. A successful profile activation followed by a cache-write failure is
reported as a partial result so you can inspect the active configuration.

The estimate applies marginal price tiers to observed outbound bytes for the
current month in the report timezone. It uses this host's assigned monthly free
allowance before charging paid tiers. Assign only the share available to this
host after other hosts/services; default **0** avoids assigning a shared account
allowance to every machine. Enter a whole-month allocation, not that allocation
minus this host's already observed usage.

The displayed calculation assumption defaults to **1,073,741,824 bytes per GB**;
you can choose **1,000,000,000**. This is an explicit estimate input, not a claim
that the provider's actual meter has been independently verified. Existing
custom profiles without a byte-unit field retain decimal GB behavior.

The estimate covers **public Internet egress only**. It excludes instance, CPU,
memory, disk, NAT Gateway, inter-zone services, taxes, discounts and other bill
items. Guest TX can include private traffic or overlapping interfaces. Monthly
usage is based on overlapping stored UTC hours; boundaries and coverage gaps
limit precision. Always inspect usage and coverage beside the price.

费用页面只估算公网出站流量，不能当作 AWS/OCI 最终账单。免费额度可能在多个服务和
主机之间共享；请输入分给本机的整月额度，默认 0。价格缓存时间、GB 换算假设、观测
流量和覆盖情况都会影响结果；实例、CPU、内存、磁盘等费用不在范围内。

## Upgrades and removal

Before upgrading, create and verify a consistent database backup from **Backup,
replay and privacy**, and retain the previous program version. Database backups
do not contain Telegram/MaxMind credentials or all managed configuration. Keep
any separately required configuration/secret backup under your own restricted
backup policy; do not attach it to public issues.

Use the native package manager or the bootstrap from the intended release.
Existing configuration is retained, and upgrades preserve disabled and masked
service choices. The v0.4 management additions retain configuration/API schema 1
and use database schema 6. Durable budget/health state and the retention ledger
are additive. See [alerts and evidence](ALERTS_EVIDENCE.md) for configuration and
export commands. New daily archives retain bounded pricing inputs;
older reports keep an empty pricing snapshot. Back up before upgrading: a
pre-schema-6 binary refuses this database and configuration recovery does not
downgrade it. A billing profile's new optional byte-unit field can be
incompatible with old binaries; do not assume that an older executable can use
new configuration or data. Restore a verified matching backup to a new path
when doing a planned downgrade; recovery never automatically downgrades a DB.

For a source-to-package transition, use the reviewed checkout:

```sh
sudo ./scripts/source-to-package.sh --prepare
# Then install the selected native package using apt or dnf, as above.
sudo /usr/bin/noderampart setup
```

The preparation validates owned binary/unit/helper hashes before stopping and
removing source-owned files. New source installs record six files; older
five-file manifests remain accepted. Pre-manifest installations require the
exact retained original build with `--legacy-checkout /absolute/original/build`.
Modified or unowned files require manual reconciliation. Data and administrator
drop-ins remain. The old source-path GeoIP timer is removed during transition;
re-enable daily updates in the native installation's menu if desired.

**Services and uninstall** offers two distinct operations:

| Operation | What remains |
| --- | --- |
| Uninstall, keep configuration and data | Configuration, credentials, database, GeoIP data and pricing cache remain for reuse. |
| Uninstall and delete all managed data | Deletes fixed `/etc/noderampart`, `/var/lib/noderampart`, `/var/cache/noderampart` trees and service accounts, after safety checks. |

The same operations use a locally installed helper, even offline:

```sh
# Native DEB/RPM installation:
sudo /usr/libexec/noderampart/manage-remove

# Source installation (choose this path only for a source install):
sudo /usr/local/libexec/noderampart/manage-remove
```

Add **`--purge`** only when you intend to delete the fixed managed data trees.
These trees may contain backups as well as active history. The helper stops
observation and the owned GeoIP timer, then uses the appropriate removal method;
system dependencies and other administrator drop-ins are retained. Both removal
choices delete the fixed managed tmpfiles rule above, preserve other tmpfiles
rules and leave the current runtime lock inode in place. Purge refuses
symlinked directories and mounts/nested mounts before deletion. It never follows
arbitrary configuration paths to delete external files.

RPM can retain an edited package configuration as `config.json.rpmsave`.
Reinstalling does not restore it automatically: review and reconcile that file
yourself. Default-preserving removal retains files without promising automatic
activation of old settings. If removal failed after the package was removed,
remaining files are not evidence of successful purge; inspect the error and
reinstall the reviewed package if you need its local helper again.

普通卸载保留配置、凭据、历史和缓存；彻底卸载需单独选择，并删除三个固定应用目录。
目录内的备份也会被删除。卸载不会删除系统依赖，也不会按配置中任意路径寻找数据删除。

## Troubleshooting

| Symptom | Next step |
| --- | --- |
| Bootstrap reports missing release / HTTP 404 | Publication is not active, or the requested release is unavailable. Use a reviewed local package. |
| Checksum, package identity or redirect rejected | Retain the refusal; obtain a complete matching release. Do not skip verification. |
| Menu cannot find a terminal | Use an interactive SSH terminal; use `--no-setup` only for the installer. |
| Status cannot reach the daemon | Inspect `systemctl status` and `journalctl` for the two observer services; run `noderampart doctor`. |
| Saved configuration did not activate | Read the error and use Recover previous configuration if a pending apply exists. Recheck status afterwards. |
| Telegram test not delivered | Check the target chat, bot access and notification outcome; saving alone sends no test. |
| GeoIP download failed | Check your own enrollment/key and HTTPS connectivity; inspect the last result and retained database age. |
| Prices appear old or unavailable | Refresh explicitly; cached prices are date-labelled and observation does not require pricing. |
| Report contains unknown coverage | Inspect Health and diagnosis. Report backfill cannot invent observations from an offline period. |

Use the [local redacted evidence exporter](ALERTS_EVIDENCE.md) for an incident
or diagnostic excerpt. Review before sharing; UTC times and counts can remain
linkable. Ordinary logs and database backups are not redacted evidence. [v0.3 operations](V0.3_OPERATIONS.md) documents incident,
silence, report, backup and replay commands in detail.

## Browsing history and reproducing prices

Report, incident and notification lists support direct selection. Timeline entries
show their saved delivery result. Next/previous controls retain the original
query period and cursors; previous pages re-read retained data, so pruning or new
records may change their content. Up to 128 page cursors are retained per
open query; change the query to revisit older cursors. Health coverage segments
also support these controls. AWS setup loads the public region list for selection;
manual region entry remains available if the region catalog cannot be reached.

New archived reports contain an optional `billing` snapshot in `report show`
JSON and in the TUI. It stores observed TX bytes, accounting period/timezone, the
full tariff profile (including source URL/date, free allowance, byte unit and
all tiers), profile SHA-256, generation time and computed estimate. Its basis is
`configured_tariff_at_generation`: historical backfill uses the configuration at
creation, not recovered historical provider rates. The profile hash detects input
changes; it is not a signed provider quote. Changing configuration later never
rewrites an archive. Old reports and reports without billing have no such input
snapshot; their original bodies are preserved. Custom rates must be finite,
nonnegative and no greater than `1e100`; source URLs are limited to 4096 bytes.

GeoIP updates still download and validate both databases. If both database files
and the full set of license notices exactly match the trusted active generation,
the update records `unchanged` and advances its check time while retaining the
activation time, configuration and running services. Changed data uses the
existing paired activation/recovery process. Credential or schedule choices made
explicitly in setup still take effect when the data is unchanged.

报告、事件及通知可直接点选，翻页自动保留时间段与游标；上一页会重新查询现存记录。
新日报附带完整计价输入，修改配置不会重算旧报告。补报采用生成时配置的费率，
并不还原过去真实账单。GeoIP 内容及许可文件相同则只更新检查时间，保留当前服务。

For checksum, provenance and SBOM verification, see [release verification](RELEASE_VERIFICATION.md).
If Debian installation stopped partway through configuration, the management
removal helper recognizes unpacked/half-configured package ownership and routes
removal through apt. Native `sudo apt remove noderampart` / `sudo apt purge
noderampart` remain the direct recovery path if the TUI cannot start.
