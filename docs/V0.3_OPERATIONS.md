# v0.3 operations

v0.3 remains an observer. It adds local inspection and replay commands without
changing the sensor/daemon privilege split or adding network listeners.
Existing [v0.2 operations](V0.2_OPERATIONS.md) cover installation, backups and
queue administration; the changes below apply to v0.3.

## Upgrade and compatibility

Back up using the running old daemon before upgrading. Stop both services,
install matching v0.3 binaries, validate configuration and restart. Schema 4
adds indexes, event delivery decisions, silences, delivery leases/coalescing
metadata and per-interface hourly detail. Migration is transactional and uses
the configured database/journal page ceiling and free-space watermark before
DDL. A refusal leaves the old schema intact; relieve pressure and retry.

Configuration schema 1, control API 1 and sensor protocol 3 remain unchanged.
Old configurations receive the new defaults; old binaries reject new fields
and cannot open schema 4. Downgrading requires the old backup and matching old
configuration/binaries. Backup verification accepts exact supported schemas
1–4; restore remains to a new file. Historical interface identities and missing
delivery relationships are not invented.

New defaults are `notifications.merge_window: "10m"` and
`reports.backfill_days: 7`. Set either to zero to disable that behavior.

## Timeline and incidents

```sh
sudo noderampart events timeline --since 2026-09-10T00:00:00Z --until 2026-09-12T00:00:00Z --limit 20
sudo noderampart incident list --since 2026-09-10T00:00:00Z --until 2026-09-12T00:00:00Z
sudo noderampart incident show --id inc_EXAMPLE --since 2026-09-10T00:00:00Z --until 2026-09-12T00:00:00Z
```

Ranges are half-open, at most eight days, with at most 100 rows. Retention is
seven days, so the boundary allowance does not promise eight days of evidence.
Timeline continuation uses both `--after` and `--after-id`; incident-list
continuation uses `--before` and `--before-id`. Keep the requested range fixed
and use the timestamps/IDs returned in the previous page.

Incident summaries expose retained start/recovery phases and first/last retained
observations. No retained recovery is not proof that an incident remains active.
SSH context uses up to eight stored source keys and 100 observations within five
minutes of retained incident phases, clipped to the requested range. Equal
prefixes and time proximity are context, not identity or proof of causation.
Hash-key changes and pruned events limit correlation.

Each event shows admission decision plus retained delivery outcome. Legacy
events use their exact existing notification dedupe key when available; pruned
outbox rows show unavailable delivery history. Summary commands omit evidence
maps and bodies; `events show --id` remains the detailed view.

## Coalescing and silences

Update events for one incident/kind/destination share the first update's fixed
merge window (0–24 hours). The latest notification-safe body and count replace
the pending summary; every event remains in the timeline. Start/observed and
recovery messages are immediately eligible. Recovery releases its pending
update summary. Attempted or claimed messages are not merge targets.

```sh
sudo noderampart notify silence add --incident inc_EXAMPLE --until 2026-09-12T15:00:00Z --reason maintenance
sudo noderampart notify silence add --kind syn_flood --until 2026-09-12T15:00:00Z
sudo noderampart notify silence list
sudo noderampart notify silence remove --id sil_EXAMPLE
```

Choose a future expiry within seven days. Incident and kind together mean both
must match. At most 128 rules are retained; expired/revoked rules are pruned on
new admission. Silences affect Telegram event alerts, including matching
pending rows; test notifications and reports remain outside their scope.

Suppressed bodies are cleared. A send already claimed may finish, and creation
reports that boundary. Failed claimed sends cannot retry after suppression.
Expiry/removal permits future alerts without sending suppressed backlog.
Delivery uses a two-minute claim lease around the bounded HTTP request and
remains at least once. A process failure after remote acceptance can duplicate
a notification. Queue state, event admission and remote delivery are distinct.

## Historical health and multiple interfaces

```sh
sudo noderampart health --since 2026-09-01T00:00:00Z --until 2026-09-12T00:00:00Z --limit 100
```

Health accepts at most 400 days and 100 coverage segments per page. Continue
using the returned offset (maximum 20,256). It separates component duration
totals, chronological segments, explicit gaps, hourly loss counters, current
storage/freshness and per-interface traffic. Gap count zero means unknown loss.
Only durable heartbeats establish recorded running time; missing, conflicting
and expired evidence is unknown. Running does not prove complete capture or
successful event persistence. There is no single trust percentage. Queries are
new read snapshots; a live heartbeat tail can change between pages.

```json
"sensor": {
  "interface": "",
  "interfaces": ["eth0", "eth1"]
}
```

Merge this fragment into a valid configuration. Explicit names must be unique,
at most eight, and cannot coexist with a nonempty legacy `interface`. With
neither selection, the sensor discovers the best main-table IPv4 and IPv6
default routes, deduplicating the interface. This supports IPv6-only hosts;
policy routing, ECMP and nexthop-object defaults need explicit selection.

Selection is reconciled every second. Device replacement/read loss resets
counter baselines. Capture restarts reset detection continuity; missing windows
cannot credit recovery. One fresh interface cannot hide another missing link.
AF_PACKET capture supports Ethernet links; unsupported links can still provide
interface counters and remain visibly unavailable to the sensor.

Flow, receive-buffer and detector capacities are divided by the configured
maximum (automatic mode budgets two). Thresholds apply per interface. Interface
totals sum selected links; overlapping bridges/tunnels can count a packet twice.
Historical detail admits 32 names per UTC hour plus an overflow bucket. Overflow
and legacy totals remain available with unknown interface identity. The health
view lists up to 100 names, reports truncation and flags detail/aggregate
inconsistency; narrow the requested range to inspect more specific periods.

## Bounded report backfill

```sh
sudo noderampart report backfill --from 2026-09-01 --through 2026-09-10
sudo noderampart report show --date 2026-09-01 --format text
```

Request at most 31 completed civil dates within the thirteen-month aggregate
horizon, interpreted in the configured report timezone. Results distinguish
generated, already present, nonexistent date, conflict and unavailable. A
timezone boundary change never replaces an existing archive. `complete` means
all requested dates were inspected; check per-date states and `conflicts`.

The command archives locally. It does not send historical Telegram messages.
`reports.backfill_days` (0–31, default 7) recovers at most two missing older dates
per 30-second scheduler pass; normal previous-day scheduling/delivery remains
deduplicated. The previous day is reserved for its normal scheduled time.

Storage errors/cancellation preserve completed dates. The control command
limits work to eight seconds and returns a resume date; rerunning is safe.
Historical reports label unknown coverage and possibly pruned seven-day event
detail. Hourly totals can remain useful without event details. Backfill cannot
restore missing observations. Attribution display is bounded to 4,096 groups;
reconciliation totals include all groups.

## Offline replay and threshold comparison

```sh
noderampart replay anonymize --input metadata.jsonl --output anonymous.jsonl
noderampart replay compare --input anonymous.jsonl --baseline baseline.json --candidate candidate.json
```

Both commands run without the daemon, active database, journal, capture, GeoIP
or notifier. The two configuration files use the normal schema/defaults; only
sensor enabled, detection thresholds and authentication settings are compared.
Live interface selection, notification merging and delivery are not simulated.

Inputs must be owned bounded regular files, not group/world writable, hardlinks
or symlinks. Parent symlink traversal and `.`/`..` path components are refused.
Output must not exist. It is published as mode 0600 only after complete input
validation; failure removes its temporary output. Ctrl-C cancels bounded work.

JSONL version 1 begins with:

```json
{"format":"noderampart-replay","version":1,"anonymized":false,"interface_limit":2}
```

Each remaining line is one of:

```json
{"type":"batch","generation":1,"batch":{"protocol_version":3,"sent_at_utc":"2026-09-11T12:00:00Z","interval_millis":1000,"interface":"lab0","flows":[],"rx_bytes":0,"tx_bytes":0,"rx_packets":0,"tx_packets":0,"inbound_syn_packets":0,"inbound_udp_packets":0,"inbound_icmp_packets":0,"kernel_packets":0,"kernel_drops":0,"kernel_stats_errors":0,"overflow_bytes":0,"overflow_packets":0,"parse_errors":0}}
{"type":"auth","auth":{"observed_at_utc":"2026-09-11T12:00:00.1Z","kind":"failure","source_ip":"192.0.2.1","source_port":40001,"user":"synthetic","method":"password","root":false,"invalid_user":false}}
```

Batch fields use the sensor protocol, including optional loss fields and bounded
flows. `generation` is metadata about successive sensor connections (1–100,000,
nondecreasing); it is not a new live wire field. Auth kinds are `failure`,
`success`, `invalid_user`, `pam_failure`; methods use the supported OpenSSH
method names, `pam` or `unknown`. Root/invalid-user flags preserve detector
semantics after usernames change. No raw journal text or payload is accepted.

All records are globally chronological, with strictly increasing per-interface
batch times. Limits: 64 MiB input/output, 100,000 records, 1 MiB per record, seven
days, eight interfaces and 65,536 address/user identities. Unknown fields,
duplicate keys, excess nesting and invalid counters are rejected without
echoing the offending values. Existing hourly exports are not replay inputs.

Pseudonymization shifts the first timestamp to `2000-01-01T00:00:00Z`, preserves
relative time, and maps identities to `ifN`, `userN`, IPv4 `198.18.0.0/15` or
IPv6 `2001:db8::/96` fixture space. Comparison requires the anonymized marker and
these spaces. These addresses are metadata only; no traffic is generated.
Output includes an input digest, effective rules, event totals/differences,
bounded detector health and at most 1,000 normalized event summaries per side.
IDs are reproducible within each side, not cross-configuration identity keys.

Pseudonymization is not a guarantee of anonymity: timings, ports, volumes and
behavior remain linkable. Loss, cold-start UDP matching and missing within-batch
ordering limit fidelity. Counts compare rule outputs, not known false-positive
rates. Inspect artifacts before sharing them.
